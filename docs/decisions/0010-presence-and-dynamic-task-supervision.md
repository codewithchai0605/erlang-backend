# 0010 - Presence: derived state, grace period, last child, dynamic task supervisor
Status: accepted
Context: Milestone 5 needs online/offline and last-seen. AGENT.md says online presence must not be the sole source of truth in PostgreSQL and asks for dynamic supervision where appropriate.
Decision: "Online" is derived from live authenticated WebSocket connections and kept by `chat_presence` (gen_server + ETS). It monitors connection pids; after a user's last connection dies it waits `CHAT_PRESENCE_GRACE_MS` before announcing offline (stale-timer pattern), so quick reconnects cause no flicker. Only transitions are announced, by short-lived `chat_task` processes under `chat_task_sup` (`simple_one_for_one`, `temporary`, capped at 500; overflow is dropped and counted). Only `users.last_seen_at` is persisted. `chat_presence` is the LAST child of the `rest_for_one` supervisor and rebuilds its state from the `pg` scope on start. Connections notify it with a `cast`.
Consequences: a presence crash disturbs nothing and heals itself (tested); the database and fan-out never block the presence process; load spikes shed announcements instead of queueing without bound (clients re-sync presence on reconnect). Cost: single-node only (no cross-node presence); presence is visible to all peers; a hard server crash leaves `last_seen_at` at the last clean transition (acceptable: it only affects the "last seen" text).
