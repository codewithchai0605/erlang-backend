# Protocol (v1)

Schema: `proto/chat/v1/chat.proto` (single source of truth). Erlang code is generated by gpb on every compile; Dart code by `scripts/dev/gen-proto.sh`. Status: the schema compiles with the real `protoc`. `proto/testdata/golden_vectors.json` holds 13 vectors, each produced three ways that must agree: a 10-line hand-written wire encoder, the official protobuf runtime on classes generated from the real `chat.proto` (`scripts/dev/make_golden_vectors.py` fails on any mismatch), and the Erlang gpb encoder (asserted in `chat_protocol_tests`; verified with gpb 4.21.7 and 5.0.0). The original five vectors are byte-identical after the Milestone 5 additions: proof the schema evolved compatibly. The Dart side is meant to assert the same bytes after regeneration.

## Transport rules

- Endpoint: `GET /ws` upgrade. Every WebSocket message is ONE binary frame holding one protobuf `ClientEnvelope` / `ServerEnvelope`. WebSocket framing already delimits messages, so no length prefix is used. Text frames are rejected (close 1003). Frames larger than `CHAT_MAX_WS_MESSAGE_BYTES` are rejected by Cowboy (close 1009).
- No JSON for chat events or message payloads. (Register/login/profile are plain HTTP JSON.)
- First message must be `Hello{protocol_version, capabilities, access_token}` within `CHAT_WS_HELLO_TIMEOUT_MS`; otherwise close 1008. The token is in the Hello message, never in the URL (URLs end up in logs).
- Protobuf has no version negotiation of its own: `protocol_version` is checked in Hello (`UNSUPPORTED_VERSION` on mismatch); `HelloAck` returns the server's limits.
- Requests carry a client-chosen `request_id`, echoed in the response. Server pushes have an empty `request_id`.
- Field numbers are never reused; removed fields are `reserved`. Unknown fields are ignored (forward compatible). An envelope whose `oneof` is empty or unknown yields `ERROR_CODE_UNSUPPORTED_EVENT`, not a crash. Server-only events (`presence`, `conversation_removed`, ...) sent by a client are rejected the same way.
- **Evolution since v1:** Milestone 5 only *added* fields and `oneof` variants, so `protocol_version` stays 1. New abilities are advertised in `HelloAck.capabilities` (`typing`, `presence`, `groups`). Old clients ignore events they do not know.
- Undecodable bytes: `INVALID_ARGUMENT` then close 1007. Semantic validation (UUID shape, text length, NUL bytes, membership) happens after decoding.
- Keepalive: WebSocket ping/pong (client pings every 20 s); server idle timeout `CHAT_WS_IDLE_TIMEOUT_MS`.

## Close codes

1000 normal, 1001 server shutting down, 1003 text frame, 1007 malformed protobuf, 1008 policy (hello missing/timeout, bad token, session revoked), 1009 frame too large.

## Requests

| Client sends | Server replies | Notes |
|---|---|---|
| `send_message` | `accepted` (+ push `new_message` to other devices/members) | idempotent on `(sender, client_message_id)`; `duplicate=true` on retry |
| `sync_request{after_seq}` | `batch` ascending | forward catch-up; `has_more` means ask again from the last seq |
| `history_request{before_seq}` | `batch` ascending | backward paging; `before_seq=0` = newest |
| `ack_delivered{up_to_seq}` | `receipt` | advances the caller's delivered mark |
| `mark_read{up_to_seq}` | `receipt` | advances read (and delivered) mark |
| `create_direct{peer_user_id}` | `conversation` (+ push to peer) | find-or-create |
| `list_conversations` | `conversation_list` | includes every member's receipt marks and roles |
| `typing{conversation_id,is_typing}` | *nothing* (fire-and-forget) + push `typing` to the other members | rate-limited; silently dropped when exceeded; errors only for non-members |
| `get_presence{user_ids}` | `presence_snapshot` | empty = all peers; non-peers omitted; offline users carry `last_seen_unix_ms` |
| `create_group{title, member_user_ids}` | `conversation` (+ push to the other members) | creator becomes owner; at least one other member; at most `CHAT_MAX_GROUP_MEMBERS` |
| `add_members{conversation_id, user_ids}` | `conversation` (+ push to all members) | owner only; new members see history only from joining |
| `remove_member{conversation_id, user_id}` | `conversation` (+ push; the target gets `conversation_removed`) | owner only; never yourself (use leave) |
| `leave_conversation{conversation_id}` | `conversation_removed` (+ push of the new member list to the others) | groups only; ownership passes on; an empty group is deleted |
| `rename_group{conversation_id, title}` | `conversation` (+ push) | owner only |

Server pushes (empty `request_id`): `new_message`, `receipt`, `conversation` (new or changed conversation), `conversation_removed`, `typing`, `presence`. **Typing and presence pushes are ephemeral:** never stored, never replayed, may be lost. Clients refresh presence with `get_presence` after reconnecting and expire typing indicators on their own.

Errors: `ProtocolError{code, message}` with the same `request_id` (a failed `typing` echoes its empty id). "Group is full" and "only group conversations can be changed" are `INVALID_ARGUMENT` with a readable message. Codes: UNSUPPORTED_VERSION, UNAUTHENTICATED, INVALID_ARGUMENT, PERMISSION_DENIED, NOT_FOUND, RATE_LIMITED, UNSUPPORTED_EVENT, INTERNAL, MESSAGE_TOO_LARGE.

## Delivery semantics (important)

- **At-least-once, effectively-once.** A message is durable before it is pushed. Retries are safe: the server stores at most one row per `(sender_id, client_message_id)`. Clients upsert by `client_message_id`, so duplicate pushes/syncs are harmless. Exactly-once is NOT promised by the transport.
- **Ordering.** `seq` is per conversation, strictly increasing, and gap-free (assigned while holding the conversation row lock). Clients keep a contiguous `sync_cursor`; a push with `seq > cursor+1` means a gap and triggers `sync_request`.
- **Three distinct states:** *accepted* (server stored it; you got `accepted`), *delivered* (recipient's device stored it; `delivered_up_to_seq >= seq`), *read* (`read_up_to_seq >= seq`). Receipts are monotonic per member, so late or duplicate updates are harmless.
- **Reconnect order:** list conversations -> sync each behind conversation -> flush outbox. Syncing first means a message whose `accepted` reply was lost is reconciled by sync instead of being sent again.
- **Slow consumers:** if a connection's mailbox exceeds `CHAT_WS_MAX_QUEUE`, the server drops it; the client reconnects and syncs.

## Groups: visibility and authorization rules

- A member can read messages with `seq > history_from_seq`, where that value is the conversation's `last_seq` at the moment they joined (0 for direct chats and group founders). It applies to `sync_request` and `history_request`; the server enforces it, not the client.
- A removed or departed member loses all access immediately (every operation re-checks membership in the database). Their old messages stay for the others; clients label the sender "Former member" if they cannot resolve the name.
- Receipts in groups: a message is *delivered*/*read* when **every other current member** reached that mark (weakest link).

## Not implemented yet

Message editing/deletion, attachments, push notifications for backgrounded apps, admin roles (the schema and enum reserve `admin`), per-user "hide my presence" setting, system messages ("Alice added Bob") in the timeline.
